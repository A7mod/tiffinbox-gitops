# Stage 2: But it worked on staging
**Status:** Done · **Started:** 2026-09-30 · **Finished:** 2026-09-30 · **Active hours:** ~3

## Business pain
Dev, staging and prod YAMLs were copy-pasted and drifted apart. Prod ran 1 replica during the lunch rush.

## What we built
- `workloads/menu-api/base`: hand-written Deployment, Service, Ingress (no Helm chart)
- `overlays/{dev,staging,prod}`: replicas 1/2/3, host, colour, image tag
- `apps/menu-api-appset.yaml`: ApplicationSet with a Git directory generator → one app per overlay
- `templatePatch`: auto-sync for dev/staging, manual sync (release gate) for prod

## How it works
- Ingress (host) → Service (port 80, selector `app: menu-api`) → Pods (9898). Labels are the glue.
- Kustomize: `replicas:`/`images:` shortcuts, strategic merge patch (merges lists by key), JSON 6902 patch (exact path)
- New env = new folder; delete the folder = env gone (namespace stays)
- Promotion = a commit moving the same image tag dev → staging → prod; prod needs `argocd app sync`

## Gotchas
- `kind: ingress` (lowercase) → the Kustomize patch target matched nothing → silently skipped
- `rule:`, `rargetRevision`, `createNamespace`: unknown or case-wrong fields fail silently or late
- A label value can't contain `/` (`{{.path.path}}` → rejected Applications)
- Habit: render → diff → `--dry-run=server` → commit
